# 架构与当前边界

插件以轻量为目标，全局输入范围固定为 `Win+Tab`、`Win+Shift+Tab`、`Alt+Tab` 和
`Alt+Shift+Tab`，分别进入工作区与窗口面板。Win 对应 Hyprland 的 Super 修饰键。
MRU 历史服务于候选排序，确认激活统一通过面板会话完成。

QML 负责 Qt 对象、界面、输入和信号；TypeScript 负责普通数据与纯逻辑；Lua 负责全局绑定。
业务 TypeScript 使用 ES2016，构建脚本使用独立 Node 类型环境。构建采用暂存目录，成功后
替换 `dist/plugin/`；Qt 测试导入同一份发布 ESM。

`HyprlandAdapter` 从 Quickshell 模型读取窗口、工作区和显示器，归一化到逻辑坐标，并读取
Omarchy 显示器编号段。窗口 key 结合地址和 QObject 生命周期，关闭/地址复用不继承旧身份。
TypeScript 的 unknown 校验边界排除无效窗口地址和断开显示器对象。

窗口候选队列在一次会话中冻结；工作区候选在桌面事件及面板开启期间的 200 ms 刷新中
按来源屏幕同步，已有项保持相对顺序，新项追加到末尾，选中项通过真实全局 ID 保持。
预览几何与候选共用最新桌面快照。
单屏窗口范围为当前普通工作区，多屏为来源显示器的普通工作区。
工作区队列固定在打开面板时聚焦的显示器，按该屏幕的 Omarchy 顶部栏规则生成：
补齐来源显示器前 5 个槽位，再包含实际位于该屏幕上的其他
编号工作区（包括来访工作区），排除命名和特殊工作区。已有空工作区和未实例化槽位都进入
概览及键盘循环，统一按当前、上一个和 MRU 排序。打开面板不实例化槽位，确认后才创建。
概览按数量排列：2 个为 1×2，4 个为 2×2，6 个为 2×3，
8 个为 2×4，9 个为 3×3。卡片优先宽度为 480 个逻辑像素，间距 16；面板宽度限制
在屏幕内，预览高度跟随来源显示器比例。选中项按卡片实际边界判断是否超出视口，
排除末行下方间距，全部可见时关闭滚动交互并保持 `contentY: 0`。
卡片只在右上角显示小号、半透明的编号/名称，选中时添加 1 像素主题色边框，背景颜色保持一致。多屏可附显示器名称，
没有底部标签、窗口数量和当前/上一个文字，也没有顶部标题或底部操作提示。
空槽位确认校验至少覆盖顶部栏的前 5 个槽位。
本地十槽全满时仍保留额外数字/来访工作区，不按本地编号去重、不限制候选数量。
选中的来访工作区移走或重新编号时取消会话；消失的来访 ID 不重建到其他显示器的编号段。
`SessionLogic` 实现 preparing/selecting/committing 转换及会话序号校验，快照前步进和确认可累计。

面板开启时抑制真实历史更新；关闭后释放独占输入，激活控制器重查目标、发送 Lua dispatch，
并在有限重试后记录最终真实焦点。工作区确认时要求目标仍属于打开面板时的来源显示器，
来源断开则关闭面板。窗口与工作区 MRU 独立维护，仅用于各自的候选排序。
激活仍在核对时到达的新打开请求在完成后处理。

命令测试使用面板 Tab 和 Enter；绑定模式使用 GlobalShortcut 作为唯一 Tab 来源。
修饰键仅在按住确认的会话中异步查询 `hl.is_key_down()`，支持左右 Alt/Super。
查询失败不按超时提交。Lua 回调通过内存中的运行状态租约降级，不执行文件 IO 或阻塞进程。
租约两秒更新一次，六秒过期；这是运行状态检测，与空闲修饰键轮询分别处理。

待同步的代码精简：从 `bindings.lua`、`Overlay.qml` 中移除旧版两对象回切绑定、
对应的 GlobalShortcut 和 `previous` IPC，清理仅为回切服务的逻辑与测试；保留候选排序
使用的焦点记录与去重。完成后安装器只接管上述四个 Tab 组合，Quake console 保持系统原绑定。

主题与翻译复用 Omarchy Commons。动态文本复用 `PlainText`。QML 工具对 ESM 导出和主题
QtObject 字段的推断边界使用局部注释，ESM 调用由 Qt 测试覆盖。本机 Quickshell 的
GlobalShortcut 元数据缺少 PostReloadHook 基类，检查工具在 `.cache/` 中补入安装版本的
原始声明，并以该目录优先进行 lint；不更改系统文件或运行时组件。

本地部署使用独立 Python 安装器，备份配置和旧插件，修改本插件条目和带标记的 include，
失败回滚；卸载保留其他条目、用户新增绑定，并可恢复安装前同 ID 插件。

`PreviewProvider` 通过完整窗口生命周期 key 解析 `HyprlandToplevel.wayland`，不会按标题
或仅按地址猜测捕获源。工作区卡片中的 `ScreencopyView` 使用 `live: true`，关闭鼠标指针
捕获，按逻辑几何等比合成窗口内容；没有首帧或捕获停止时显示应用图标/名称。
可见卡片才加载捕获组件，滚出视口及关闭面板时销毁组件。窗口 key 列表没有变化时，
几何刷新保留原捕获组件，避免每次刷新重建视频流。候选顺序和选中项保持稳定。
预览背景复用 `Ui.BackgroundMedia`，使用 `background_cache.py` 在独立进程中预生成的 PNG，
最长边不超过 960 像素。缓存身份包含壁纸真实路径、设备与 inode、大小及纳秒级 mtime/ctime，
同名文件替换也会刷新；生成期间壁纸变化则丢弃该结果并重试，缓存写入使用原子替换。
磁盘缓存位于 `${XDG_CACHE_HOME:-~/.cache}/omarchy-switchboard/backgrounds/`，最多保留四张。
`BackgroundCacheController` 提前异步解码小图并保留引用；所有卡片按小图原生尺寸加载，共享该解码，
避免面板关闭时 Qt 淘汰未引用的缓存，也避免卡片尺寸变化重新解码原壁纸。
替换壁纸时先准备新图再发布；一张缩略图的解码像素最多为 960×960，切换时最多同时保留两张。
没有窗口的卡片仅显示壁纸；壁纸不可用或为视频时保留主题背景。壁纸链接使用文件监听、每两秒轮询
及打开时检查，面板关闭后仍准备壁纸缓存。实时窗口捕获仍只在面板可见期间运行。

尚未实现窗口图像 LRU 和完整性能统计；`constraintSize` 只约束显示尺寸，不代表源缓冲降分辨率。
普通命名工作区（例如 `a`）的候选、显示和确认适配记录于 [已知问题](known-issues.md)，
当前仍跟随 Omarchy 默认顶部栏，只列出数字工作区。
窗口模式仍使用图标/标题。双屏、混合 DPI、旋转、全屏、XWayland、模态/分组、锁屏中断和真实
键盘释放时序需要桌面验收；纯逻辑测试不代表这些场景已通过。
